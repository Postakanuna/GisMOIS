ОПИСАНИЕ ПРОГРАММЫ ДЛЯ ЭВМ

Государственная информационная система Московской области «Инженерные сети»
(ГИС МО «ИС»)

============================================================================
1. ОБЩИЕ СВЕДЕНИЯ
============================================================================

Наименование программы:
  Государственная информационная система Московской области «Инженерные сети»
  (сокращённо: ГИС МО «ИС»)

Правообладатель:
  Министерство энергетики Московской области

Оператор системы:
  Государственное казённое учреждение Московской области «Агентство развития
  коммунальной инфраструктуры» (ГКУ МО «АРКИ»)

Основание создания:
  Распоряжение Министерства энергетики Московской области № 33-Р

Статус информации:
  Государственный информационный ресурс Московской области

============================================================================
2. НАЗНАЧЕНИЕ И ОБЛАСТЬ ПРИМЕНЕНИЯ
============================================================================

Цель создания программы — повышение эффективности реализации полномочий
Министерства энергетики Московской области, требующих автоматизации.

Основные задачи:
  — Формирование карт и моделирование инженерных сетей;
  — Разработка GIS-приложений, требующих визуализации пространственных данных;
  — Анализ топологии данных и их связи с семантическими базами данных;
  — Мониторинг мероприятий, предусмотренных техническими условиями подключения
    объектов капитального строительства.

Область применения:
  Управление инженерной инфраструктурой Московской области в сферах
  теплоснабжения, водоснабжения, водоотведения, газоснабжения и
  электроснабжения.

============================================================================
3. ФУНКЦИОНАЛЬНЫЕ ХАРАКТЕРИСТИКИ
============================================================================

Система обладает модульной структурой и обеспечивает следующие функции:

  1) Создание всевозможных карт, включая схемы инженерных сетей с поддержкой
     топологии.
  2) Формирование собственных структур данных: слои, условные обозначения,
     таблицы с атрибутами, справочники, шаблоны отчётов.
  3) Использование данных картографических веб-сервисов (WMS/WFS).
  4) Совместный семантический и пространственный анализ графических и табличных
     данных.
  5) Экспорт и импорт данных (GeoJSON, Shapefile, XLSX).
  6) Подготовка и публикация данных для веб-версии.
  7) Работа с мобильными устройствами через веб-службы.
  8) Удалённый доступ и работа через веб-службы.
  9) Обмен данными с устройствами промышленной автоматизации.
 10) Геокодирование адресов (прямое и обратное) с использованием внешних
     сервисов (Яндекс Геокодер, DaData) с поддержкой ФИАС.
 11) Автоматическое подключение потребителей к тепловой сети с расчётом
     параметров трубопровода (AI-модель или эвристический метод), маршрутизацией
     через OSRM, размещением тепловых камер и анализом пропускной способности.
 12) AI-ассистент с поддержкой RAG (Retrieval-Augmented Generation) для
     интеллектуальных запросов по данным ГИС. Динамическое управление
     AI-провайдерами (OpenAI, Yandex GPT, LMStudio, Ollama и любые
     OpenAI-совместимые сервисы) через панель администратора.
 13) Валидация топологии инженерных сетей: проверка связности, обнаружение
     разрывов, тупиков и циклов в графе сети.
 14) Трассировка маршрутов по графу сети: определение пути от потребителя
     до источника с визуализацией на карте.
 15) Моделирование сетевых сценариев (network simulation): анализ последствий
     отключения участков сети (задвижек, узлов) с выявлением отключённых
     потребителей.
 16) Анализ жалоб и обращений с привязкой к объектам инфраструктуры:
     автоматический поиск связанных элементов сети вблизи адреса жалобы.
 17) Геопространственная аналитика: буферные зоны, анализ плотности,
     статистика по атрибутам, пространственные запросы.
 18) Иерархическая организация слоёв по папкам (layer_folders) и сцен
     по папкам (scene_folders).
 19) История изменений объектов (feature_history) с возможностью отслеживания
     версий.
 20) Управление пользовательскими иконками (custom_icons) для стилизации
     точечных объектов.
 21) Настройка привязки (snapping) при рисовании объектов к существующей
     геометрии.
 22) Присоединение данных из Excel (Attribute Join) — обогащение данных слоя
     сопоставлением ключевых полей из XLSX-файла.
 23) Профиль пользователя с возможностью редактирования персональных данных.
 24) Посадочная страница (landing page) с описанием возможностей системы.
 25) Анализ аварийности трубопроводных сетей: автоматическое пространственное
     связывание аварийных событий с участками трубопроводов (радиус привязки
     до 15 м), статистика аварийности по участкам с атрибутами (диаметр,
     система, длина), группировка и ранжирование участков по количеству аварий,
     экспорт результатов в Excel. Запуск инструмента через AI-ассистента
     (маркер [ACTION:ACCIDENT_ANALYSIS:...]). Сохранение результатов в
     редактируемый слой карты в виде буферных полигонов (5 м вокруг аварийных
     участков) с атрибутами. Нормализация и валидация геометрии трубопроводов
     перед буферизацией (обработка edge-cases: неправильный регистр типа,
     строковые координаты, null-точки, однопунктовые LineString).
     Потоковая передача прогресса выполнения анализа (Server-Sent Events):
     сервер отправляет события поэтапно (привязка аварий → построение графа
     → симуляция по участкам), клиент отображает живые промежуточные результаты
     без блокирующего ожидания. Граф сети строится однократно и переиспользуется
     для всех участков. Пользователь может отменить анализ в процессе выполнения.
     Опциональный анализ отключений потребителей и жителей (симуляция разрыва
     сети): для каждого аварийного участка определяется количество отключённых
     потребителей (Kol_potreb) и жителей (Kol_zhit) на основе пространственного
     моделирования графа сети. Результаты сохраняются в атрибуты буферных
     полигонов. При сохранении результатов в слой автоматически создаётся или
     обновляется схема атрибутов слоя (layer_schema), обеспечивая корректное
     отображение всех сохранённых полей в атрибутивной таблице.
 26) Принудительная перезагрузка кэша геометрии карты: кнопка в панели
     управления картой (правый верхний угол) для одновременного сброса
     клиентского кэша объектов (до 20 000 записей) и серверного кэша
     (TTL 30 сек) с последующей автоматической перезагрузкой актуальной
     несжатой геометрии для текущего вида карты.

4. СТРУКТУРА СИСТЕМЫ (ПОДСИСТЕМЫ)
============================================================================

Система состоит из 12 подсистем, объединённых в единый программный комплекс.
Подсистемы 1–6 реализованы в рамках собственной разработки (веб-приложение).
Подсистемы 7–12 реализованы на базе лицензионного программного обеспечения
ZuluGIS (ООО «Политерм», https://www.politerm.com/products/geo/zulugis/),
лицензия на которое приобретена в рамках создания ГИС МО «ИС».

Обмен данными между веб-подсистемами (1–6) и расчётными модулями (7–12)
осуществляется по стандартным картографическим протоколам WMS (Web Map Service)
и WFS (Web Feature Service), что обеспечивает бесшовную интеграцию и единое
информационное пространство всех подсистем.

Перечень подсистем:

  1. Подсистема «Организация многопользовательской работы и мониторинга
     системы».
     Обеспечивает многопользовательский доступ с ролевой моделью (администратор,
     оператор, наблюдатель), аутентификацию, управление сценами (рабочими
     пространствами) с иерархической группировкой по папкам, управление
     участниками сцен с раздельными правами доступа (владелец, редактор,
     наблюдатель), аудит действий пользователей с автоматической ротацией
     журнала. Профили пользователей с персональными данными (ФИО, должность,
     организация, контакты). Система баг-репортов со скриншотами и статусами
     обработки. Глобальные настройки приложения (app_settings).

  2. Подсистема «Работа системы в мобильных устройствах через веб-службы».
     Адаптивный веб-интерфейс для работы с картографическими данными и
     инженерными схемами на мобильных устройствах.

  3. Подсистема «Удалённый доступ и работа в системе через веб-службы».
     REST API для удалённого доступа к функциям системы, управление API-ключами
     с поддержкой активации/деактивации, внешний API с трассировкой запросов,
     кросс-сценовый поиск объектов по атрибутам и координатам.

  4. Подсистема «Обмен данными с устройствами в промышленной автоматизации».
     Интерфейсы для интеграции с устройствами промышленной автоматизации,
     обмен данными в стандартизированных форматах.

  5. Подсистема «Разработка геоинформационных плагинов в системе-библиотеке
     интернет-компонентов».
     Модульная архитектура с возможностью расширения функционала через
     подключаемые компоненты (слои, стили, инструменты анализа). Поддержка
     пользовательских SVG-иконок (custom_icons), категоризированных и
     градуированных рендереров, стилей по ГОСТ для тепловых сетей.

  6. Подсистема «Настройка пользовательского интерфейса для веб-версии
     системы».
     Конфигурируемый интерфейс с тёмной/светлой темой, панелью слоёв
     с иерархической организацией по папкам (layer_folders),
     инструментами рисования с настройкой привязки (snapping), измерения,
     атрибутивными таблицами с фильтрацией и сортировкой, легендой,
     панелью поиска, посадочной страницей и координатным дисплеем.

  7. Подсистема «Внешнее подключение приложений по стандарту COM к внутренним
     подсистемам расчётов схем» (на базе ZuluGIS).

  8. Подсистема «Работа со схемами стационарных и передвижных систем
     теплоснабжения и горячего водоснабжения» (на базе ZuluGIS).

  9. Подсистема «Работа со схемами систем водоснабжения» (на базе ZuluGIS).

 10. Подсистема «Работа со схемами систем водоотведения» (на базе ZuluGIS).

 11. Подсистема «Работа со схемами систем газоснабжения» (на базе ZuluGIS).

 12. Подсистема «Работа с данными теплоисточников» (на базе ZuluGIS).

5. МЕЖМОДУЛЬНОЕ ВЗАИМОДЕЙСТВИЕ
============================================================================

Подсистемы 1–6 (веб-приложение) и подсистемы 7–12 (ZuluGIS) объединены
в единый программный комплекс посредством стандартных протоколов обмена
картографическими данными:

  — WMS (Web Map Service) — протокол получения растровых карт (изображений)
    от ZuluGIS-сервера. Веб-приложение запрашивает картографические слои
    инженерных сетей (теплоснабжение, водоснабжение, газоснабжение и др.)
    и отображает их на интерактивной карте.

  — WFS (Web Feature Service) — протокол получения векторных данных
    (пространственных объектов с атрибутами) от ZuluGIS-сервера.
    Веб-приложение использует WFS для доступа к свойствам объектов,
    фильтрации, пространственного анализа и редактирования данных.

Данная архитектура обеспечивает:
  — Единое информационное пространство для всех 12 подсистем;
  — Возможность одновременной работы с данными веб-подсистем и расчётных
    модулей ZuluGIS на одной карте;
  — Стандартизированный обмен данными по открытым протоколам OGC.

6. СОСТАВ ИНФОРМАЦИИ (БАЗА ДАННЫХ)
============================================================================

Система обрабатывает следующий перечень документированной информации:

  — Сведения о функциональных возможностях системы;
  — Сведения о пользователях (учётные записи, роли, права доступа,
    персональные данные);
  — Данные о пространственных объектах (векторные, растровые цифровые
    представления) с историей изменений;
  — Инженерные схемы: водоснабжения, водоотведения, теплоснабжения,
    газоснабжения, электроснабжения;
  — Инвестиционные программы регулируемых организаций и государственные
    программы Московской области;
  — Схемы расположения передвижных объектов теплоснабжения и
    электроснабжения;
  — Карты подосновы Московской области и карты границ городских округов;
  — Данные о сценах (рабочих пространствах) с иерархией папок;
  — Данные о наборах данных (datasets), их объектах (dataset_features)
    и привязке к сценам (scene_datasets);
  — Журнал аудита действий пользователей;
  — Сведения об ошибках (баг-репорты со скриншотами);
  — Ключи внешнего API;
  — Конфигурации AI-провайдеров;
  — Диалоги AI-ассистента (conversations, messages);
  — Пользовательские иконки (custom_icons);
  — Загруженные файлы (uploads);
  — Схемы атрибутов слоёв (layer_schemas);
  — Глобальные настройки приложения (app_settings).

Структура базы данных определена в схеме PostgreSQL и включает таблицы:
users, sessions, scenes, scene_members, scene_folders, datasets,
dataset_features, scene_datasets, drawn_features, feature_history,
editable_layers, layer_folders, layer_schemas, custom_icons, uploads,
api_keys, app_settings, audit_log, bug_reports, ai_providers,
conversations, messages.
