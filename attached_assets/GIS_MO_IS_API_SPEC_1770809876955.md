# Техническое задание на доработку API ГИС МО Инженерные сети

## Контекст

АРМ АРКИ (система управления проектами ИП/ГП Министерства энергетики МО) интегрирована с ГИС МО ИС для получения пространственных данных об инженерных сетях в зоне строительных объектов.

Текущий API-эндпоинт `GET /api/external/layers/:layerId/features-in-polygon` выполняет пространственный анализ **по всем полигонам** в указанном слое. Однако каждый проект в АРМ АРКИ привязан к **одному конкретному полигону** (объекту) внутри слоя. Необходим новый эндпоинт, позволяющий запрашивать данные по конкретному полигону.

## Требуемый новый эндпоинт

### `GET /api/external/layers/:layerId/features-in-polygon/:featureId`

Выполняет пространственный анализ пересечения объектов инженерных сетей с **одним конкретным полигоном** (feature) внутри указанного слоя.

### Параметры пути

| Параметр    | Тип    | Описание |
|-------------|--------|----------|
| `layerId`   | number | ID полигонального слоя (тот же, что используется в существующем эндпоинте `features-in-polygon`) |
| `featureId` | string | Уникальный идентификатор конкретного полигона (feature) внутри слоя `layerId` |

### Query-параметры (опциональные)

| Параметр            | Тип      | Описание |
|---------------------|----------|----------|
| `sourceLayerIds`    | number[] | Массив ID слоёв-источников для анализа пересечений. Если не указан — анализируются все доступные слои |
| `includeAttributes` | string[] | Список атрибутов, которые нужно включить в ответ для каждого найденного объекта |

### Заголовки

| Заголовок      | Значение              | Описание |
|----------------|-----------------------|----------|
| `Authorization` | `Bearer <api_token>` | Токен доступа к API (существующая авторизация) |
| `Accept`        | `application/json`   | Формат ответа |

### Формат ответа (200 OK)

### Поле `boundaryFeature` (новое)

Дополнительное поле `boundaryFeature` в ответе содержит информацию о конкретном полигоне, по которому выполнен анализ. Это позволяет вызывающей системе подтвердить, что данные получены именно по запрошенному объекту.

### Коды ошибок

| Код | Описание |
|-----|----------|
| 200 | Успешный ответ с результатами анализа |
| 400 | Некорректные параметры (layerId не число, featureId пустой, слой не полигональный) |
| 401 | Невалидный или отсутствующий токен |
| 403 | Токен не имеет доступа к указанному слою/сцене |
| 404 | Слой с `layerId` не найден **ИЛИ** полигон с `featureId` не найден в указанном слое |

### Формат ошибки 404 (feature не найден)

```json
{
  "error": "Not found",
  "message": "Feature with id '127842' not found in layer 42"
}
```

## Логика работы

1. Найти слой по `layerId` (существующая логика)
2. Найти конкретный полигон (feature) по `featureId` внутри этого слоя
3. Использовать геометрию **только этого полигона** как границу для пространственного анализа
4. Выполнить пересечение (intersection) геометрий объектов из слоёв-источников с геометрией найденного полигона
5. Вернуть результат в формате, совместимом с существующим эндпоинтом

## Совместимость

- Существующий эндпоинт `GET /api/external/layers/:layerId/features-in-polygon` **не изменяется** и продолжает работать как прежде
- Новый эндпоинт является расширением и использует ту же авторизацию и те же слои

## Пример вызова из АРМ АРКИ

```
GET /api/external/layers/42/features-in-polygon/127842
Authorization: Bearer eyJhbGciOi...
Accept: application/json
```

Где:
- `42` — ID полигонального слоя «Объекты строительства»
- `127842` — уникальный ID конкретного строительного объекта внутри этого слоя
